# ScreenDrop — полная проектная документация

**Версия:** 1.0 | **Статус:** Initial Development Specification | **Дисциплина:** Системное программирование

## 1. Назначение
ScreenDrop — автономная локальная система обмена файлами между смартфонами, компьютерами и Android-экранами. Преподаватель запускает приём файлов на Android TV, студент открывает web-страницу по QR-коду и отправляет документ через браузер.

## 2. Проблема
Передача через мессенджеры, облака и USB требует лишних действий, интернета или физического подключения накопителя. ScreenDrop предоставляет локальную веб-страницу, размещённую на Android TV.

## 3. Цели MVP
1. Установить APK на совместимый Android TV.
2. Подключить TV к Wi-Fi, предпочтительно к Hotspot смартфона.
3. Запустить встроенный HTTP-сервер.
4. Создать сессию и QR-код.
5. Открыть страницу на телефоне/ПК.
6. Передать PDF и другие поддерживаемые файлы.
7. Сохранить файл локально.
8. Рассчитать SHA-256.
9. Просмотреть, открыть и удалить файл.

## 4. Роли
**Teacher:** запускает/останавливает приём, показывает QR, управляет файлами и сессией.  
**Student:** сканирует QR, выбирает файлы в браузере, отправляет их.  
Отдельная административная роль не входит в MVP.

## 5. Архитектура
Android TV — сервер; браузер — клиент. Компоненты: Compose UI, Network Manager, Server Lifecycle Manager, Ktor HTTP Server, Session Manager, Upload Manager, File Storage, Metadata Repository, Web Sender.

Поток: `Browser → Wi-Fi/LAN → Ktor → Session validation → Streaming upload → Temporary file → SHA-256 → Finalize → Metadata → TV UI`.

## 6. Сетевые режимы
**Personal Hotspot:** смартфон включает Hotspot, TV подключается. После получения сетевых параметров приложение проверяет, может ли телефон обращаться к HTTP-серверу TV.

**Existing Wi-Fi:** оба устройства подключены к одной сети. Клиентская изоляция также может блокировать связь.

**Критическое ограничение:** реализация Hotspot и маршрутизация зависят от Android-версии и производителя. Наличие IP или успешный bind сервера не доказывают доступность с телефона. До полной реализации требуется физический proof of concept: GET и POST с телефона на TV без интернета.

**Fallback:** если телефон не может обратиться к TV, показать диагностику. Будущий Phone Transfer Hub (телефон — сервер, TV — клиент) является отдельным режимом, не частью обязательного MVP.

## 7. Технологии
- Kotlin, Android SDK
- Jetpack Compose / Material 3
- Ktor Server
- Kotlin Coroutines / Flow
- ConnectivityManager / NetworkCallback / LinkProperties
- ZXing
- HTML/CSS/JavaScript
- JUnit и Android instrumentation tests

Не требуются Python/Node backend, PostgreSQL, Redis, Firebase, VPS или Docker.

## 8. Начальные лимиты
- Максимальный файл: 100 MiB (конфигурируемо).
- Параллельные загрузки: 3.
- Порт: 8080.
- Таймаут бездействия сессии: 30 минут.
- Форматы: PDF, PPT/PPTX, DOC/DOCX, TXT, JPG/JPEG, PNG, MP4.
- Приватное хранилище приложения.

## 9. Безопасность
Токен — криптографически случайный, минимум 128 бит энтропии, предпочтительно 256 бит. Все операции с файлами требуют авторизации. Проверять размер, имя, тип и лимиты. Записывать во временный файл, незавершённое не публиковать. SHA-256 — контроль целостности, не аутентификация. HTTP не шифрует трафик.

## 10. Приёмка
MVP принимается, если на физических устройствах APK запускается на TV, UI управляется пультом, сервер запускается, QR открывается на телефоне, PDF передаётся без интернета, файл сохраняется, SHA-256 совпадает, файл можно открыть, неверный/истёкший токен отклоняется, потеря сети не публикует неполный файл.

## 12. Definition of Done
Все P0 требования SRS реализованы и проверены. Непроверенные функции помечены. Эмуляторный тест не выдаётся за физический Hotspot-тест.
