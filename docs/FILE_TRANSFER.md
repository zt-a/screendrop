# File Transfer Specification

## Форматы
PDF, PPT, PPTX, DOC, DOCX, TXT, JPG, JPEG, PNG, MP4. Наличие расширения не гарантирует наличие viewer на TV.

## Начальные лимиты
- 100 MiB на файл;
- 3 параллельные загрузки;
- имя до 255 символов;
- сессия истекает после 30 минут бездействия;
- ограниченный буфер потоковой записи.

## Алгоритм
1. Browser отправляет multipart POST.
2. Сервер проверяет token.
3. Получает слот concurrency.
4. Проверяет размер до и во время чтения.
5. Создаёт временный файл с внутренним случайным ID.
6. Потоково читает multipart.
7. Записывает блоки и обновляет SHA-256.
8. Проверяет успешное завершение.
9. Закрывает/сбрасывает output.
10. Атомарно перемещает файл, если файловая система это поддерживает.
11. Сохраняет metadata.
12. Возвращает 201.

При ошибке временный файл удаляется или помечается для очистки.

## Схема
```text
Multipart stream → bounded buffer → temp file + SHA-256
                                      |
                               successful finish?
                                 /          \
                               yes           no
                               |             |
                           finalize       delete temp
                               |
                           metadata
```

## Имена
Не использовать клиентское имя как путь. Удалять разделители и управляющие символы. Хранить безопасное display name отдельно. Использовать opaque internal ID. Не перезаписывать файлы.

## Проверка типа
Проверять extension, заявленный MIME и сигнатуру там, где практично. Не исполнять загруженные файлы.

## Metadata
id, originalName, safeDisplayName, sizeBytes, mimeType, sha256, senderName, receivedAt, status.

## Открытие
Использовать Intent + FileProvider + content URI. Не использовать file:// URI. Если viewer отсутствует, показать сообщение.

## Очистка
Удалять старые `.part` по TTL, не затрагивая завершённые файлы.
