# Security Specification

## Модель угроз
Несанкционированная загрузка, перехват HTTP, Path Traversal, подмена MIME/имени, исчерпание RAM/диска/соединений, вредоносные файлы, утечка токена.

## Токены
Использовать SecureRandom/криптографически стойкий генератор. Минимум 128 бит энтропии, предпочтительно 256. Не строить токен из IP, времени или счётчика. Не логировать. Закрывать сессию после занятия. Старый токен должен инвалидироваться.

QR виден аудитории, поэтому любой, кто его сфотографирует, может получить токен. Использовать короткую сессию и кнопку немедленного закрытия.

## HTTP/TLS
HTTP не шифрует файл, токен и метаданные. Токен не заменяет TLS. Не заявлять конфиденциальность или защиту от MITM. Для production рассмотреть HTTPS с понятной моделью доверия.

## Upload
- лимит размера до и во время чтения;
- concurrency limit;
- filename sanitization;
- путь только из внутреннего ID;
- ограничение multipart parser;
- temp file до завершения;
- cleanup при ошибке;
- атомарная финализация, где возможно;
- не открывать автоматически.

## API
Health возвращает минимум информации. List/upload/delete/session endpoints требуют token. Проверять токен на каждом запросе. Не принимать локальный путь от клиента.

## Resource exhaustion
Ограничить размер, число загрузок, длину полей, частоту запросов и использование диска. Освобождать Semaphore в finally.

## Логи
Не логировать токены, содержимое файлов и полные URL с токеном. Допустимы event type, opaque ID, error code, duration и size.

## SHA-256
Контроль целостности; не шифрование и не аутентификация.

## Checklist
- [ ] Неверный токен отклоняется.
- [ ] Закрытая сессия не принимает upload.
- [ ] Path Traversal невозможен.
- [ ] Сверхлимитный файл отклоняется.
- [ ] Concurrency ограничен.
- [ ] Прерванный файл не публикуется.
- [ ] Токены отсутствуют в логах.
- [ ] Storage приватный.
- [ ] HTTP limitation документирован.
