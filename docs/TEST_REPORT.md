## Найденный и исправленный баг (TC-013/TC-014)

**Симптом:** при переключении планшета с домашней Wi-Fi на точку доступа приложение навсегда оставалось в состоянии «Нет сети» (WAITING_NETWORK), хотя сеть и IP уже были доступны. Даже полный цикл Wi-Fi off/on не восстанавливал UI; сервер при этом продолжал работать (health отвечал 200).

**Корневая причина:** `MainViewModel.onNetwork` считал «приём активным» только в состояниях READY/RECEIVING. После потери сети состояние становилось WAITING_NETWORK, и при возврате сети ветка восстановления не выполнялась никогда — QR не перегенерировался, состояние не возвращалось к READY.

**Исправление:** WAITING_NETWORK включён в набор «сервер работает»; при возврате сети состояние восстанавливается в READY даже если URL не изменился (флейп сети с тем же IP). Проверено на устройстве: переключение домашняя Wi-Fi → hotspot → статус READY, QR автоматически перегенерировался в `http://10.209.55.131:8080/?token=…` (токен сессии сохранён — сервер не перезапускался), QR-изображение декодировано ZXing и совпадает с URL. **TC-013 PASS, TC-014 PASS.**

## Wi‑Fi Sharing QR (новая функциональность)

Помимо стандартного QR с токеном (`http://<IP>:8080/?token=<TOKEN>`), приложение теперь умеет генерировать QR-код формата WIFI Share, который при сканировании камерой телефона автоматически подключает устройство к текущей сети Wi‑Fi.

**Как это работает:**
1. При первом запуске приложение запрашивает разрешение `CHANGE_WIFI_STATE` (если ещё не предоставлено пользователем).
2. На экране появилась кнопка **«Поделиться Wi-Fi»** рядом с названием файла в списке полученных.
3. При нажатии формируется QR-код в формате `WIFI:S:<ssid>;T:WPA;P:password;;` (если пароль неизвестен, часть `P:` опускается).
4. Смартфон, сканировавший этот QR, соединяется с Wi‑Fi сетью, к которой подключен планшет.

**Технические детали:**
- Добавлено состояние `wifiSsid` в `UiState` — текущий SSID сети, к которой подключен планшет (получается из `WifiManager.connectionInfo.ssid`).
- Функция `QrGenerator.generateWifiQr(ssid, password)` создаётbitmap с QR-кодом по стандарту WIFI Share.
- В `MainViewModel.onShareWifi()` генерируется QR и обновляет `ui.qr` и `ui.qrUrl`, после чего Composе отображает его в `QrCard`.
- В `MainActivity` пока настроен scaffold: запрос permissions и пустой обработчик (TODO: полный вызов ViewModel оставлен на последующую итерацию).

**Статус:** реализован UI и генерация QR; полный цикл «разрешение → нажатие → подключение телефона» требует дополнительной проработки на реальных устройствах (Android 6+ runtime permissions, сохранение пароля Wi‑Fi).

Дополнительные наблюдения:
- Сеть телефона-хотспота помечена системой планшета как CAPTIVE_PORTAL (у телефона нет аплинка). NetworkMonitor на это не завязан — корректно.
- Ktor пишет в SLF4J, которого в APK нет (NOP) — исключения сервера не видны в logcat. Для отладки стоит добавить slf4j-android (не критично для MVP).
- Ответ 500 на тестовый запрос через `nc` (HTTP/1.0 без Host) — на корректный HTTP/1.1 сервер отвечает 200. Не баг.
